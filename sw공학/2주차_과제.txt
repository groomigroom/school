1. 선형 순차적 모델 (Linear Sequential Model)

* 개념: 요구분석, 설계, 개발, 테스트가 물 흐르듯 일직선으로 진행되는 방식입니다. 이전 단계가 완전히 끝나야만 다음 단계로 넘어갈 수 있습니다.
* 특징: 구조가 단순하여 이해하기 쉽고 관리가 편합니다.
* 단점: 개발이 끝나기 전까지는 실제 작동하는 소프트웨어를 볼 수 없습니다. 만약 마지막 테스트 단계에서 요구사항이 바뀌거나 큰 오류가 발견되면 처음으로 돌아가야 해서 비용이 막대하게 듭니다.
* 적합한 곳: 요구사항이 명확하고 절대 바뀔 리 없는 프로젝트.

작업 내용: 도서정보, 대여정보, 사용자 정보 등으로 포함되어야 함.

선형 순차적 모델(Waterfall Model)을 적용하여 마을 기증 도서관의 도서관리 프로그램을 구축하고, 여기에 외부 사용자 관리 기능을 업데이트(확장)하는 전체 프로세스 설계안입니다.
선형 순차적 모델은 이전 단계가 완벽히 끝나야 다음 단계로 진행되므로, 최초 구축 시점과 업데이트 시점 모두 각 단계를 엄격히 구분하여 진행해야 합니다.
------------------------------
## 📋 [1단계] 최초 구축: 도서관리 프로그램 개발 프로세스
선형 모델의 흐름에 따라 요구사항 정의 ➔ 설계 ➔ 구현 ➔ 테스트 ➔ 유지보수 순서로 일직선 진행합니다.
## 1. 요구사항 분석 (Requirements)
개발 시작 전, 도서관에서 필요한 모든 기능 요구사항을 확정하여 명세서를 작성합니다.

* 도서 정보: 도서 등록(ISBN, 도서명, 저자, 기증자 정보), 수정, 삭제, 조회
* 사용자 정보: 마을 주민 회원가입(이름, 연락처, 주소), 회원 등급 관리
* 대여 정보: 도서 대출(대출일, 반납예정일), 반납, 연체 확인, 대여 이력 관리

## 2. 시스템 및 데이터베이스 설계 (Design)
요구사항을 바탕으로 프로그램의 구조와 DB를 설계합니다. 앞서 질문하신 MySQL 구조를 활용합니다.

* 사용자 테이블 (users): userid (PK), username (NOT NULL), password (NOT NULL), user_type (주민/관리자) 등
* 도서 테이블 (books): book_id (PK), title, author, donor (기증자) 등
* 대여 테이블 (rentals): rental_id (PK), userid (FK), book_id (FK), rent_date, return_date 등
* ※ 이때 부모(users, books) 삭제 시 대여 이력 관리를 위해 ON DELETE CASCADE를 쓸지, 아니면 기록을 남길지 설계 단계에서 확정해야 합니다.

## 3. 구현 및 개발 (Implementation)
설계서가 완성되면 변경 없이 그대로 코딩을 진행합니다.

* UI 화면(도서 검색창, 대여/반납 버튼 등) 개발
* MySQL 연동 및 데이터 처리 로직 구현

## 4. 테스트 (Testing)
개발이 완료되면 실제 도서관 환경과 유사하게 데이터를 넣고 검증합니다.

* 책이 정상적으로 대여되고 반납 예정일이 잘 계산되는지 확인합니다.
* 오류가 없다면 시스템을 도서관에 정식 배포합니다.

------------------------------
## 🔄 [2단계] 업데이트: 외부 사용자 관리 기능 추가 프로세스
이미 선형 모델로 구축된 시스템에 '외부 사용자 관리'라는 새로운 요구사항이 발생했습니다. 선형 모델에서는 중간에 슬그머니 코드를 고치는 것이 불가능하므로, 업데이트 작업을 하나의 '새로운 선형 순차 프로젝트'로 취급하여 처음부터 다시 단계를 밟아야 합니다.

[기존 시스템 배포 완료] 
       ⬇
1. 요구사항 분석: 외부 사용자 정의 및 정책 수립
       ⬇
2. 설계: 테이블 구조 변경 및 외래키(FK) 재설정
       ⬇
3. 구현: 외부인 회원가입 및 제한 로직 개발
       ⬇
4. 테스트: 내부/외부인 권한 분리 검증 및 배포

## 1. 업데이트 요구사항 분석
외부 사용자의 이용 범위와 제약 조건을 명확히 정의합니다.

* 외부 사용자 정의: 마을 주민이 아닌 인근 지역 방문객
* 차별화 정책: 대여 가능한 도서 권수 제한(예: 주민 5권, 외부인 2권), 최대 대여 기간 축소(예: 주민 14일, 외부인 7일)
* 필수 정보: 외부인은 가입 시 보증금 여부나 연락처 인증 필수

## 2. 데이터베이스 및 시스템 재설정 (Design)
기존 users 테이블 구조를 변경하고 권한 로직을 설계합니다.

* 회원 구분 컬럼 변경: users 테이블에 외부인을 구분할 수 있는 user_role(주민, 외부인, 관리자) 컬럼 추가
* 제약 조건 수정: 외부인 데이터가 삭제될 때 관련 대여 정보 처리를 어떻게 할지 결정 (필요시 외래키에 ON DELETE CASCADE 또는 SET NULL 적용)

## 3. 업데이트 구현 (Implementation)

* 화면 수정: 회원가입 화면에 '주민' / '외부인' 선택 기능 추가
* 백엔드 로직 추가: 대여 프로세스 실행 시, 로그인한 유저가 '외부인'이면 대여 권수와 기간을 체크하여 제한하는 코드 구현

## 4. 통합 테스트 및 배포 (Testing & Deployment)

* 테스트 케이스 실행:
1. 외부인 계정으로 로그인 후 3권 이상 대여 시도 시 차단되는지 확인
   2. 주민 계정은 기존대로 5권까지 잘 빌려지는지 확인 (기존 기능 손상 여부 확인)
* 테스트 통과 후 최종 도서관 시스템에 업데이트 버전을 배포합니다.

------------------------------
선형 순차적 모델의 핵심은 "소프트웨어가 단계별로 단단하게 굳어지며 진행된다"는 점입니다. 따라서 외부 사용자 기능을 넣을 때 기존 소스코드를 무작정 수정하기보다는, 수정할 화면과 DB 구조를 먼저 문서로 명확히 설계(Design)한 뒤 구현(Coding)에 착수하시는 것이 선형 모델의 원칙에 맞습니다.
현재 사용 중이신 프로그래밍 언어(Java, Python, Node.js 등)나 프레임워크를 알려주시면, 외부 사용자를 구분하고 대여 권수를 제한하는 구체적인 코드 예시나 DB 변경 SQL 문을 작성해 드릴 수 있습니다. 어떻게 진행해 볼까요?
