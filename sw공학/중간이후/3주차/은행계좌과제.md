# 은행 계좌 관리 시스템 설계 원리 분석 보고서

## 1. 개요

은행 계좌 관리 시스템은 고객의 계좌 개설, 입금, 출금, 계좌 조회, 이체 및 거래 내역 관리 등의 기능을 제공하는 소프트웨어이다.

이러한 시스템을 안정적이고 효율적으로 개발하기 위해서는 소프트웨어 설계 원리를 적용해야 한다. 대표적인 설계 원리인 분할과 정복, 추상화, 캡슐화, 정보은닉, 상속, 다형성을 은행 계좌 관리 시스템에 적용하여 설명하고자 한다.

## 2. 설계 원리별 적용 내용

| 설계 원리  | 은행 계좌 관리 시스템 적용 사례                                       | 관련 내용 및 설명                                                                                                                         |
| ------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 분할과 정복 | 계좌 관리, 고객 관리, 입출금 관리, 이체 관리, 거래 내역 관리 기능으로 시스템 분리        | 복잡한 시스템을 여러 개의 작은 기능으로 나누어 개발하는 방법이다. 각 기능을 독립적으로 설계하고 구현하면 개발 및 유지보수가 쉬워지며, 오류 발생 시 해당 기능만 수정할 수 있다.                              |
| 추상화    | 은행 계좌의 공통적인 기능을 계좌(Account)라는 개념으로 정의                    | 불필요한 세부 구현을 제외하고 중요한 속성과 기능만 표현하는 방법이다. 계좌번호, 예금주, 잔액 등의 공통 속성과 입금, 출금, 잔액 조회 등의 기능을 추출하여 계좌 객체를 설계할 수 있다.                         |
| 캡슐화    | 계좌번호, 잔액 등의 데이터와 입금, 출금 등의 기능을 하나의 계좌 클래스로 구성            | 데이터와 데이터를 처리하는 기능을 하나로 묶는 방법이다. 계좌 정보와 관련 기능을 하나의 클래스로 관리하면 데이터의 일관성을 유지하고 외부에서 임의로 데이터를 변경하는 것을 방지할 수 있다.                         |
| 정보은닉   | 계좌 잔액을 외부에서 직접 변경하지 못하도록 제한하고 입금 및 출금 메서드를 통해서만 변경       | 객체 내부의 중요한 데이터나 구현 내용을 외부에 공개하지 않는 원리이다. 예를 들어 잔액(balance)을 private으로 선언하여 외부에서 직접 접근하지 못하게 하고, 출금 메서드에서 잔액 부족 여부를 확인한 후 처리하도록 한다. |
| 상속     | 일반 계좌(Account)를 부모 클래스로 만들고 입출금 계좌 및 정기예금 계좌를 자식 클래스로 구성 | 기존 클래스의 속성과 기능을 새로운 클래스가 물려받아 사용하는 방법이다. 공통 기능을 부모 클래스에 정의하고 자식 클래스에서 필요한 기능을 추가하면 코드의 중복을 줄이고 재사용성을 높일 수 있다.                      |
| 다형성    | 일반 계좌의 출금 기능을 입출금 계좌와 정기예금 계좌에서 각각 다르게 구현                | 동일한 메서드 이름이나 인터페이스를 사용하더라도 객체의 종류에 따라 서로 다른 기능을 수행하는 원리이다. 예를 들어 출금 메서드를 각 계좌 유형에 맞게 재정의하면 계좌 종류에 따라 서로 다른 출금 규칙을 적용할 수 있다.        |

## 3. 설계 원리 적용 예시

실제 은행 계좌 관리 시스템을 객체지향 방식으로 설계한다면 다음과 같이 구성할 수 있다.

| 클래스 및 기능        | 주요 역할                        | 적용 설계 원리       |
| --------------- | ---------------------------- | -------------- |
| Account         | 계좌번호, 예금주, 잔액 및 공통 입출금 기능 관리 | 추상화, 캡슐화, 정보은닉 |
| SavingsAccount  | 일반 예금 계좌의 입출금 및 이자 관리        | 상속, 다형성        |
| CheckingAccount | 자유로운 입출금이 가능한 계좌 관리          | 상속, 다형성        |
| Customer        | 고객 정보 및 고객별 계좌 관리            | 캡슐화            |
| Transaction     | 입금, 출금, 이체 등의 거래 내역 관리       | 추상화, 캡슐화       |
| AccountManager  | 계좌 개설, 조회, 삭제 및 계좌 관리 기능 수행  | 분할과 정복         |

## 4. 결론

은행 계좌 관리 시스템을 설계할 때 여섯 가지 설계 원리를 적절하게 적용하면 시스템의 안정성과 효율성을 높일 수 있다.

분할과 정복을 통해 복잡한 시스템을 기능별로 나누고, 추상화와 캡슐화를 통해 객체의 구조를 체계적으로 설계할 수 있다. 또한 정보은닉을 적용하여 계좌 잔액과 같은 중요한 데이터를 보호할 수 있으며, 상속과 다형성을 활용하면 코드의 재사용성과 확장성을 높일 수 있다.

따라서 이러한 설계 원리들은 은행 계좌 관리 시스템의 개발뿐만 아니라 향후 새로운 금융 서비스 기능을 추가하거나 시스템을 유지보수하는 데에도 중요한 역할을 한다.

과제 작성 시 참고할 점: 여섯 가지 설계 원리를 모두 은행 계좌 관리 시스템에 적용할 수 있으므로, 특정 원리만 선택하기보다는 위와 같이 각각의 적용 사례와 설명을 함께 작성하는 것이 적절하다.
