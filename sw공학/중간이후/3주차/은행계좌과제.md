# 은행 계좌 관리 시스템 설계 원리 적용 보고서

## 1. 개요

은행 계좌 관리 시스템은 고객의 계좌 개설, 입금, 출금, 계좌 조회, 이체 및 거래 내역 관리 등의 기능을 제공하는 소프트웨어이다.

이러한 시스템을 안정적이고 효율적으로 개발하기 위해서는 적절한 소프트웨어 설계 원리를 적용해야 한다. 본 보고서에서는 분할과 정복, 추상화, 캡슐화, 정보은닉, 상속의 다섯 가지 설계 원리를 은행 계좌 관리 시스템에 적용하여 설명하고자 한다.

## 2. 설계 원리별 적용 내용

| 설계 원리  | 은행 계좌 관리 시스템 적용 사례                                 | 관련 내용 및 설명                                                                                                    |
| ------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 분할과 정복 | 계좌 관리, 고객 관리, 입출금 관리, 이체 관리 기능으로 시스템 분리            | 복잡한 시스템을 여러 개의 작은 기능으로 나누어 개발하는 방법이다. 기능별로 독립적으로 설계하면 개발과 유지보수가 쉬워지고 오류 발생 시 해당 기능만 수정할 수 있다.                 |
| 추상화    | 은행 계좌의 공통적인 기능을 Account 클래스로 정의                    | 불필요한 세부 구현을 제외하고 중요한 속성과 기능만 표현하는 방법이다. 계좌번호, 예금주, 잔액 등의 공통 속성과 입금, 출금, 잔액 조회 기능을 계좌 객체로 설계할 수 있다.            |
| 캡슐화    | 계좌 정보와 입금, 출금 기능을 하나의 계좌 클래스로 구성                   | 데이터와 데이터를 처리하는 기능을 하나로 묶는 방법이다. 계좌 정보와 관련 기능을 하나의 클래스로 관리하여 데이터의 일관성을 유지하고 효율적으로 관리할 수 있다.                    |
| 정보은닉   | 계좌 잔액을 외부에서 직접 변경하지 못하도록 제한                        | 객체 내부의 중요한 데이터를 외부에서 직접 접근하지 못하도록 하는 원리이다. 잔액을 private으로 선언하고 입금 및 출금 메서드를 통해서만 변경하도록 하여 잘못된 잔액 변경을 방지할 수 있다. |
| 상속     | Account 클래스를 부모 클래스로 만들고 예금 계좌와 입출금 계좌를 자식 클래스로 구성 | 기존 클래스의 속성과 기능을 새로운 클래스가 물려받아 사용하는 방법이다. 공통 기능을 부모 클래스에 정의하면 코드 중복을 줄이고 새로운 계좌 유형을 추가하기 쉬워진다.                 |

## 3. 설계 원리 적용 예시

실제 은행 계좌 관리 시스템을 객체지향 방식으로 설계한다면 다음과 같이 구성할 수 있다.

| 클래스 및 기능        | 주요 역할                        | 적용 설계 원리       |
| --------------- | ---------------------------- | -------------- |
| Account         | 계좌번호, 예금주, 잔액 및 공통 입출금 기능 관리 | 추상화, 캡슐화, 정보은닉 |
| SavingsAccount  | 예금 계좌의 입출금 및 이자 관리           | 상속             |
| CheckingAccount | 자유로운 입출금이 가능한 계좌 관리          | 상속             |
| Customer        | 고객 정보 및 고객별 계좌 관리            | 캡슐화            |
| Transaction     | 입금, 출금, 이체 등의 거래 내역 관리       | 추상화, 캡슐화       |
| AccountManager  | 계좌 개설, 조회, 삭제 및 계좌 관리 기능 수행  | 분할과 정복         |

## 4. 결론

은행 계좌 관리 시스템에 다섯 가지 설계 원리를 적용하면 시스템의 안정성과 효율성을 높일 수 있다.

분할과 정복을 통해 복잡한 시스템을 기능별로 나누어 관리하고, 추상화와 캡슐화를 통해 객체의 구조를 체계적으로 설계할 수 있다. 또한 정보은닉을 적용하여 계좌 잔액과 같은 중요한 데이터를 보호하고, 상속을 활용하여 코드의 재사용성과 확장성을 높일 수 있다.

따라서 이러한 설계 원리들은 은행 계좌 관리 시스템의 개발뿐만 아니라 향후 새로운 금융 서비스 기능을 추가하거나 시스템을 유지보수하는 데에도 중요한 역할을 한다.

참고: 다형성을 제외한 이유는 상속과 함께 설명되는 경우가 많고, 이번 과제에서는 계좌 유형별 기능을 구분하는 정도만으로도 시스템의 객체지향 설계 구조를 충분히 설명할 수 있기 때문이야. 다만 다형성도 중요한 객체지향 설계 원리이므로, 과제에서 여섯 가지를 모두 요구한다면 다시 포함하는 것이 좋아.
